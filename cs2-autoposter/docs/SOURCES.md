# Источники и live-адаптеры

Встроен официальный Steam News API (app 730), только `steam_community_announcements`. Сторонние агрегаторы Steam не допускаются автоматически. Источник опрашивается cron раз в минуту, новости старше 6 часов и слухи не ставятся в очередь. Обычная публикация требует работающего Codex runner. При недоступности Codex новости остаются pending; выдуманного «готового текста» нет.

RSS/Atom адаптер поддерживает официальные разрешённые ленты. Перед добавлением проверьте условия источника, разрешённое использование текста/изображений, частоту и домен. Добавьте запись миграцией или через D1:

```sql
INSERT INTO sources(id,name,kind,url,official) VALUES('team-news','Официальная команда','rss','https://YOUR-TEAM-DOMAIN/feed.xml',1);
```

Нельзя отмечать агрегатор/слуховой канал официальным только чтобы обойти проверку. Сервер сам не скрейпит HLTV, Twitch или другие сайты. После пяти последовательных ошибок источник выключается; панель Sources позволяет восстановить его после исправления. Остальные источники продолжают работать. Новости разных источников объединяются URL/хешем/сходством нормализованного заголовка; aliases в src/news.ts.

## Live

В `src/providers.ts` определены `LiveProvider.read` и строгая `matchEvent` схема. Провайдер передаёт собственный ID, возрастающую revision, тип события, стабильные ID команд, турнир, BO, score, завершённые maps, winnerId, confirmed и occurredAt (или null). Никогда не используйте timestamp начала опроса как время конца матча.

Канонический вход: `POST /webhooks/live`, `Authorization: Bearer PROVIDER_WEBHOOK_TOKEN`. Это адаптерный контракт приложения, а не обещание прямой совместимости с фирменным webhook PandaScore/GRID. Преобразователь подписанного события поставщика должен проверить подпись по его документации и сопоставить поля этому контракту. Пример события — `MockLiveProvider.event('finished')`. Изучите unit/integration tests: несуществующий победитель, ничьи карты, неподтверждённый финал и несовпадающий счёт отклоняются.

PandaScore REST watcher включается только после настройки токена и `PROVIDER_POLLING_APPROVED=true`, с `PROVIDER_MIN_POLL_SECONDS` из контракта, `PROVIDER=pandascore`. POST `/api/watch` {"id":"NUMERIC_MATCH_ID"}. Durable Object перезапускает alarm после каждого опроса; GitHub Actions в этот путь не входит. Final-score REST интеграция намеренно возвращает ошибку, если нет всех round scores: получите лицензированный webhook или реализуйте полный адаптер по документации вашего доступа. Нельзя выдумывать карты, чтобы пройти валидацию.
