# Telegram

1. Создайте отдельного тестового бота через BotFather и приватный тестовый канал, добавьте бота администратором с правом отправки сообщений.
2. В `.dev.vars` (локально) или Wrangler secrets (облако) укажите `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID` и `TELEGRAM_TEST_CHANNEL_ID`. Последние два должны совпадать. Числовые IDs задаются строками, например `-1001234567890`.
3. MODE=test. Панель -> Настройки -> «Создать тестовый пост». Это реальная отправка только в явно разрешённый тестовый канал. Проверьте PNG, подпись, статус published, message_id и время.
4. Для mock-матча включите «Автоматическая обработка публикаций», затем «Начать NAVI × Vitality» и «NAVI побеждает 2:1». Повтор второй кнопки не создаёт дубль.
5. MODE=production требует `PRODUCTION_CONFIRM=I_UNDERSTAND_LIVE_POSTING`, настоящий канал, подтверждённый live-провайдер и отдельного бота. Mock и кнопка тестовой отправки в production запрещены. Новый production-деплой не делается автоматически.

Не выводите переменные окружения и URL Bot API, содержащие токен. Не включайте HTTP debug logging. Ошибки в D1 содержат только код, компонент и ID. Созданный проект не читает и не копирует токен старого автопостера. До настройки MODE=test/production отправок не будет, даже если в shell уже есть Telegram-токен.

Для uncertain: найдите пост в канале вручную, затем POST `/api/posts/reconcile` с админским ключом и JSON `{"id":"POST_UUID","message_id":123}`. Если сообщения нет, запись оставьте uncertain до окончательной проверки; интерфейс не предлагает опасную кнопку «повторить».
