# Архитектура и границы гарантий

Worker обслуживает защищённую панель, Telegram outbox, API редактора, Steam/RSS и cron раз в минуту. Cloudflare D1 — единственная основная БД; состояние не коммитится в GitHub. Durable Object на матч сериализует события и хранит alarm частого мониторинга. Доступ к API только по отдельным случайным bearer-ключам администратора, runner и провайдера. Передавать их только по HTTPS. В панели ключ хранится лишь в памяти вкладки. Закройте панель Cloudflare Access дополнительно, особенно в production.

Codex CLI не запускается в Worker: нужен постоянно работающий Linux VPS / self-hosted runner с вашим интерактивным ChatGPT login. Он забирает задания по атомарной lease из D1. API-ключ OpenAI не используется. Ограничения подписки сохраняются. Не переносите файл авторизации в GitHub Secrets или артефакты; отдельный сервер с закрытым диском проще и надёжнее эфемерного hosted runner. При истечении login обычные новости остаются в очереди, результаты матчей используют встроенный шаблон.

## Срочный путь

`started` сохраняет два варианта заголовка, графическую конфигурацию и демонстрационные PNG обоих исходов в prepared_assets. Необязательное задание Codex уточняет заголовки. `finished` должен быть подтверждён провайдером; проверяются BO, победитель, счёт каждой завершённой карты, согласованность серии и монотонность revision. Готовый заголовок + подтверждённые цифры -> локальный SVG -> resvg WASM -> PNG -> Telegram. Ни Codex, ни скачивание фото/шрифтов не входят в срочный путь. Шрифт встроен в bundle. Заголовок, счёт и шаблон рендерятся только из проверенного события.

`map_finished` сохраняет счёт и состояние для панели. Отдельный пост на каждую карту/начало не отправляется автоматически: основной быстрый пост — окончательный результат серии. `cancelled`/`corrected` отменяет очередь; после отправленного результата регистрируется ошибка для разбирательства. Самостоятельно исправлять историческое сообщение по неподтверждённому событию система не будет.

## 20 секунд

Это цель, не SLA. Система не знает, когда физически закончился матч, пока провайдер не предоставил достоверный timestamp. `occurred_at=null` сохраняет неизвестность, а не подставляет время опроса. `received_at` фиксируется на входе Durable Object. `sent_at` после ответа Telegram. `detection_ms=received_at-occurred_at`, `processing_ms=sent_at-received_at`. Для dry-run метрика относится к локальной имитации отправки; это не доказательство скорости реального Telegram или источника. Cold start, WASM, лимиты CPU, сеть и задержка провайдера могут вывести за 20 секунд. Для resvg нужен план Workers с достаточным CPU; начните с Paid и измерьте свой размер шаблона.

Production live-провайдер не выбран автоматически. REST PandaScore интегрирован для начала наблюдения, но не объявлен полноценным final-score источником: обычный endpoint не гарантирует round scores каждой карты. Финалы приходят через документированный канонический webhook с полными лицензированными данными. GRID подключается своим адаптером к тому же интерфейсу; универсального GRID endpoint и схемы для всех контрактов нет. Поставщик должен разрешать частоту запросов. Минимальный интервал задан контрактом, настройка панели его не уменьшает. HTTP webhook отвечает только после обработки; провайдер может повторить событие с тем же ID. Mock работает без внешних ключей.

## Доставка и сбои

Уникальный `event_key` в D1 + `UPDATE ... WHERE status='ready'` обеспечивают одного отправителя. Telegram не предоставляет idempotency key для sendPhoto и не имеет метода поиска произвольного исходящего сообщения по вашему event ID: обещать exactly-once невозможно. При timeout, 5xx, некорректном ответе или падении после send ставится `uncertain`; повтора нет. Администратор вручную проверяет канал и подтверждает message_id через `/api/posts/reconcile`. 429 с корректным `retry_after` — безопасный отказ до отправки, не более пяти попыток; cron повторяет после срока. Явный 4xx — `rejected`. Нет автоматического удаления и повторной публикации.

D1 хранит PNG; для минимальных шаблонов это десятки КБ. Для больших фотографических PSD-экспортов добавьте R2 и сохраняйте в D1 только ключ: лимит D1 строки/значения нельзя игнорировать. Внешние фото по URL по умолчанию не загружаются: используйте встроенные data URI подготовленных изображений.

Надёжность новостей опирается на разрешённый официальный источник. Evidence и числа автоматически сверяются с текстом, но это не математическая проверка смысла перевода. Невозможно доказать достоверность произвольного текста одним LLM. Для чувствительных публикаций нужны дополнительные доменные верификаторы; слухи фильтруются консервативно. Дедуп объединяет нормализованные URL, ID, точные хеши и близкие заголовки. Семантически разные языковые формулировки могут потребовать ручных alias/event ID или специализированного адаптера.
